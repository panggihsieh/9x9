# 因數分解互動板

一個限時因數分解互動遊戲。玩家可以從 1 到 100 選數字，找出因數、觀察因數配對，並透過拖放或點選完成質因數分解挑戰。

## 版本

- 第一版：教學示範。點選左側數字後，自動顯示因數、因數配對與質因數分解。
- 第二版：遊戲測驗。用左側數字板點選或拖拉作答，三個任務都要按確認鍵；連續三次錯誤會顯示正確答案，並加入總倒數與本題倒數。
- 第三版：[班級測驗 Web App](https://x9-factor-game.web.app/v3/)。老師以 Gmail 加 4 位數字通行碼驗證優先權，學生透過班級代碼加入，即時查看答題狀態與排行榜。

## 玩法

- 按「開始測驗」啟動 60 秒倒數。
- 1、2、3 三個小題各自有 35 秒倒數，按「開始本題」後才開始計時與播放滴答聲。
- 選擇任務區後，點選或拖曳左側數字來作答。
- 因數、因數配對、質因數分解三區都要完成確認。
- 答對會加秒，答錯會扣秒，完成整題會得到速度獎勵。
- 可切換靜音；測驗進行中有倒數滴答聲，答對會出現喝采和彩帶特效。
- 答對越快、連擊越高，分數越高。

直接開啟 `index.html` 即可遊玩。

## Web App

發布到 GitHub Pages 後可作為 PWA 使用。支援加入手機主畫面，並透過 service worker 快取主要檔案。

## 第三版：降低 Firestore 配額消耗（2026-09-17）

### 調整原因

Firestore 讀取次數不是人數或作答次數。舊版每位學生每 15 秒把在線時間寫入大家都監聽的班級文件，容易產生「一人回報、全班各讀一次」的放大效果。例如 30 位學生使用 10 分鐘，理想化估算為 `30 × (600 / 15) × 30 = 36,000` 次班級文件通知；這不是帳單精確值，尚未包含規則相依讀取、交易、排行榜及其他查詢。

舊版每 30 秒統計全站人數時，也會先讀取所有班級、包含歷史學生紀錄，再於瀏覽器篩選。控制台曾出現 `Quota exceeded`，因此先改善資料流，而不是直接要求升級付費方案。

### 新的資料流

- `classrooms/{code}` 保留開始、結束、班級模式、時間設定與加入人數等課堂事件。學生不再定期寫入此文件。
- `roomPresence/{sessionId}` 分別保存老師及學生最後活動時間。此文件不由全班監聽；只供開課、閒置釋放與管理查詢使用。
- 學生每 60 秒以同一個批次更新自己的學生文件及獨立在線紀錄；作答、換題時在原交易中一併更新在線紀錄。最近已回報的學生略過多餘心跳。
- 老師每 60 秒更新獨立在線紀錄。老師的即時排行榜仍監聽學生答題資料，學生只監聽自己的資料及班級事件。
- 在線顯示使用 150 秒容忍窗口，配合 60 秒回報；「可釋放」仍需老師與學生雙方離線至少 5 分鐘。
- 全站查詢只讀 `waiting`、`active` 班級，以及 `sessionId` 符合本次課堂的學生，使用 Firestore 查詢條件，不再掃描歷史學生。
- 全站人數快取 60 秒，同一頁共用進行中的查詢，同一網站分頁透過 localStorage 共用最近人數。這是近似在線數，並非精確的原子全站名額鎖；每班加入人數仍由原交易保護。
- 隱藏分頁停止課堂監聽與心跳，回到前景時重新訂閱。若所有老師／學生分頁都隱藏或離線超過 5 分鐘，班級可能被視為可釋放；上課時請保持課堂頁在前景。
- 課堂結束會取消學生監聽；配額錯誤顯示中文訊息，背景輪詢退避 5 分鐘。退避不代表免費配額已恢復。

### 資料與舊版相容

釋放不會刪除歷史成績。規則同時檢查原班級時間與新在線紀錄，以較新的活動保護班級；仍支援舊頁面的回報。發布後應重新整理所有老師／學生舊分頁，否則舊程式仍可能每 15 秒回報。5 分鐘釋放仍由開啟中的頁面檢查或開課時判斷，不是伺服器排程。

新的方案移除了學生心跳觸發全班讀取的主要來源，但不保證每月零費用；監聽、規則驗證、交易及重新連線仍會產生用量。改善幅度應以相同學生數、相同上課時間比較 Firebase 用量，勿以短期估算當作帳單保證。

### 本機測試（不消耗正式資料庫配額）

在專案根目錄執行：

```powershell
node --test tests/*.test.cjs tests/*.test.mjs
npx --yes firebase-tools@13.35.1 emulators:exec --config firebase.emulators.json --only firestore,auth --project demo-factor-game "node tests/firestore-live.cjs"
```

第二個指令使用與本機 Java 17 相容的 Firebase CLI 版本，模擬器只監聽本機。若使用新版 Firebase CLI，需依其要求安裝 Java 21 以上。`demo-factor-game` 是本機測試專案，測試不取得正式 Firebase CLI 憑證；測試資料寫入與清除皆在模擬器。

正式環境測試仍需明確設定 `RUN_FIRESTORE_LIVE=x9-factor-game`，日常開發不要執行，以免消耗學生上課用量。

驗證結果：28 項程式測試、75 項本機資料庫整合檢查通過，涵蓋驗證權限、計分防重複、獨立在線回報及閒置釋放。計費依據參考 [Firebase 官方 Firestore 讀取與監聽計費說明](https://firebase.google.com/docs/firestore/pricing#listening_to_query_results)。
